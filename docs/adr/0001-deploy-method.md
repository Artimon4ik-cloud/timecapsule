\# ADR 0001: Способ развертывания TimeCapsule



\## Статус



Принято



Дата: 2026-10-01



\## Контекст



Приложение TimeCapsule работает на виртуальном сервере AWS EC2 в регионе eu-central-1.



Код проекта хранится в GitHub. Нам нужен способ, с помощью которого новую версию проекта можно переносить с компьютера разработчика на сервер EC2.



Мы рассмотрели три варианта:



1\. SCP

2\. Ручной git pull

3\. Скрипт deploy.sh



\## Вариант 1: SCP



При помощи SCP можно напрямую копировать файлы с компьютера на сервер EC2.



Плюсы:

\- Простой способ.

\- Не обязательно использовать Git на сервере.



Минусы:

\- Файлы нужно копировать вручную.

\- Можно случайно забыть какой-то файл.

\- Сложнее понять, какая версия проекта сейчас находится на сервере.



\## Вариант 2: Ручной git pull



Сначала изменения отправляются с компьютера в GitHub через git push.



После этого мы подключаемся к EC2 через SSH и выполняем git pull, чтобы получить новую версию.



Плюсы:

\- Просто использовать.

\- Git хранит историю изменений.

\- Можно посмотреть, какая версия находится на сервере.

\- Можно сделать откат через Git.



Минусы:

\- Нужно вручную выполнять несколько команд.

\- Если во время обновления произойдет ошибка, сайт может временно перестать работать.



\## Вариант 3: deploy.sh



Можно создать скрипт deploy.sh, который сам выполняет основные команды обновления проекта.



Например:

\- git pull;

\- composer install;

\- обновление базы данных;

\- перезапуск PHP-FPM.



Плюсы:

\- Нужно выполнять меньше команд вручную.

\- Каждый раз выполняются одинаковые шаги.

\- Меньше вероятность забыть какую-то команду.



Минусы:

\- Скрипт тоже нужно создавать и поддерживать.

\- Если одна из команд завершится с ошибкой, развертывание может остановиться.

\- Это еще не полноценный CI/CD.



\## Решение



Для данной лабораторной работы выбран ручной способ развертывания через Git.



Сначала изменения делаются на локальном компьютере. Затем выполняются git commit и git push, и код отправляется в GitHub.



После этого мы подключаемся к EC2 через SSH и выполняем git pull. Затем устанавливаем зависимости через Composer, проверяем базу данных и перезагружаем PHP-FPM.



Этот вариант подходит для нашей лабораторной работы и варианта Informatică aplicată, потому что он простой и позволяет хорошо понять каждый этап развертывания.



\## Последствия



Плюс этого способа в том, что процесс достаточно простой, а Git хранит историю всех изменений.



Минус в том, что обновление приходится выполнять вручную. В более крупном проекте этот процесс можно автоматизировать с помощью deploy.sh или CI/CD.
