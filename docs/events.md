# TimeCapsule — события приложения

## capsule.sealed

Событие создаётся после успешного сохранения новой капсулы
в базе данных PostgreSQL.

Приложение публикует событие в Amazon SNS.
SNS передаёт его в очередь Amazon SQS, откуда его
получает Lambda-функция timecapsule-dev-mailer.

### Формат события

```json
{
  "event_type": "capsule.sealed",
  "capsule_id": 42
}
```

### Описание полей

| Поле | Тип | Назначение |
|---|---|---|
| event_type | string | Тип события |
| capsule_id | integer | Идентификатор созданной капсулы |

Значение capsule_id в примере условное.

### Обработка события

1. Lambda получает сообщение из SQS.
2. Определяет тип события и идентификатор капсулы.
3. Получает необходимые данные из PostgreSQL.
4. Ожидает MAIL_DELAY_SECONDS секунд.
5. Создаёт запись в таблице notifications.
6. При повторной доставке события не создаёт дубликат уведомления.

### Безопасность

В событии передаются только тип события и идентификатор капсулы.

Не передаются:

- содержимое капсулы;
- вложенные файлы;
- электронная почта пользователя;
- пароли;
- данные подключения к базе данных.

Все необходимые данные Lambda получает непосредственно
из PostgreSQL.

Это уменьшает размер сообщения и предотвращает передачу
лишних конфиденциальных данных через SNS и SQS

# Автоматическое открытие капсул — Lambda Opener

## 1. Назначение

Ранее открытие капсул выполнялось PHP-приложением
при посещении сайта пользователем.

В рамках лабораторной работы №7 данный механизм
был перенесён в AWS Lambda.

Теперь капсулы открываются автоматически,
даже если никто не посещает сайт.

## 2. Используемые ресурсы AWS

| Ресурс | Название |
|---|---|
| Lambda | timecapsule-dev-opener |
| EventBridge Scheduler | timecapsule-dev-open-capsules |
| SNS Topic | timecapsule-dev-events |
| RDS | lab5-db |
| IAM Role | timecapsule-dev-opener-role |

## 3. Принцип работы

1. EventBridge Scheduler каждую минуту запускает Lambda.
2. Lambda подключается к PostgreSQL.
3. Выполняется поиск капсул, время открытия которых наступило.
4. Обновляется поле opened_at.
5. В таблицу notifications добавляются уведомления.
6. Изменения сохраняются в базе данных.
7. Lambda возвращает результат выполнения.
8. Lambda Destination отправляет результат в SNS.
9. SNS проверяет политику фильтрации и отправляет письмо.

## 4. Событие capsule.opened

Пример результата выполнения Lambda:

```json
{
  "event_type": "capsule.opened",
  "opened_count": 1,
  "capsules": [
    {
      "capsule_id": 16,
      "title": "Lambda Opener Test"
    }
  ]
}
```

Описание полей:

- event_type — тип события.
- opened_count — количество открытых капсул.
- capsules — список открытых капсул.
- capsule_id — идентификатор капсулы.
- title — название капсулы.

## 5. Фильтрация SNS

Для подписки электронной почты используется
фильтрация по содержимому сообщения (Message body).

```json
{
  "responsePayload": {
    "event_type": ["capsule.opened"],
    "opened_count": [
      {
        "numeric": [">", 0]
      }
    ]
  }
}
```

Письмо отправляется только тогда, когда Lambda
успешно открыла хотя бы одну капсулу.

Если opened_count равен нулю, письмо не отправляется.

## 6. Защита от повторной обработки

Lambda обрабатывает только капсулы,
у которых opened_at IS NULL.

Для предотвращения дублирования уведомлений
используется SQL-конструкция:

```sql
ON CONFLICT (capsule_id, event_type) DO NOTHING
```

Обновление капсул и создание уведомлений
выполняются в рамках одной транзакции.

При возникновении ошибки выполняется rollback.

## 7. Lambda Destination

Для успешных асинхронных вызовов Lambda
настроен Destination с типом SNS Topic.

Lambda не отправляет сообщения в SNS напрямую
из Python-кода.

Преимущества:

- Упрощение программного кода.
- Разделение бизнес-логики и доставки событий.
- Отсутствие необходимости прямого сетевого
  подключения Lambda к SNS.

При прямой отправке сообщения из Lambda,
расположенной в приватных подсетях, потребовался бы
NAT Gateway или VPC Endpoint для SNS.

## 8. Возможные ошибки

Если база данных недоступна, Lambda не сможет
открыть капсулы.

После восстановления базы данных очередной
запуск обработает просроченные капсулы.

Если транзакция успешно завершилась, но доставка
события в SNS завершилась ошибкой, капсула останется
открытой, а уведомление сохранится в базе данных.

При этом электронное письмо может быть не доставлено.
Для гарантированной доставки можно дополнительно
использовать механизм Transactional Outbox.

## 9. Выбор интервала запуска

EventBridge Scheduler запускает Lambda каждую минуту:

rate(1 minute)

Такой интервал позволяет открывать капсулы
с небольшой задержкой.

Более редкие запуски уменьшают количество вызовов
Lambda, но увеличивают задержку открытия капсул.

Открытие капсул успешно перенесено из PHP-приложения

пользователей и выполняется автоматически
с помощью Lambda и EventBridge Scheduler.
